## What this is
A personal music library manager for one user (owner@example.com): library (artists, albums, releases, tracks, playlists, "relational bios" = `groups`, timeline, notes) plus a **ranking system** (head-to-head votes → Elo → 0–10 rating) and playback queue rules ("play B right after A"). Originally generated with Dyad/Gemini (hence odd comments, `dyad-*` files). Being refactored heavily. The goal is that it is easy to iterate on.

## Decisions made (don't re-ask)
| Topic | Decision |
|---|---|
| Shape | Local-first. The server is optional: clients work alone and sync to it when connected. No mandatory frontend/backend split. |
| Server | Self-contained Node server for a **Raspberry Pi + external HDD**. Custom storage location (`CURATOR_DATA_DIR`). Default port **47813** (user asked for something obscure, not 8080). Token auth. |
| Clients | Web (desktop + mobile browser), **Electron** desktop app (real local storage), **native Kotlin + Media3 Android app** (needed for Android Auto). |
| Web storage | Browser can't hold GBs: web client gets a **storage capacity bar/limit**; Electron/Android hold full offline copies. Files copy server → local for offline use; server hosts songs not saved locally. |
| Android Auto | Verified: works **only** for a native media app (`MediaLibraryService`/`MediaBrowserService` + `MediaSession`); PWA/WebView cannot. No Play Store needed for personal use: enable Android Auto developer mode (tap "Version and permission info" 10×) → "Unknown sources". Doesn't apply to Cars App Library apps. Android Auto draws the UI itself; no custom media UI while driving. Sources: developer.android.com/training/cars/media and /training/cars/testing. |
| UI / theming | New **default theme**: stylish, **medium density** (spacious cover-art grids for browsing + compact table rows for ranking/editing lists). Must **not** be "too dense". Current look is preserved as an alternate **"Classic"** theme. Build a real theme system (CSS variables) and user options; the user loves theming. The old **rating UI** was painful to get right with the AI; preserve its behaviour/look in Classic. |
| Keep intact | Elo voting, playback rules, relational bios, yt-dlp album import (make cross-platform, move to server). |
| Theming | **Not in this repo any more.** Palettes, UI styles, wallpaper, effects and the generic `.btn/.input/.card` rules live in the **turbothemes** package, which now lives in the **turboengine** repository (`themes/` folder, github.com/TurboNZL/turboengine; the old separate turbothemes repository is retired), shared by all the owner's apps. Curator only starts its engine (`apps/web/src/lib/appearance.ts`) and keeps the picker UI. See the last section; everything about the theme CSS below this line is history. |
| Elo storage | Elo/comparisons/rating are **derived** by replaying the append-only `votes` log, never stored. Makes multi-device voting mergeable. |

The handoff came from another app (BudgetTrack, shadcn). Its colour data, UI-style ideas and wallpaper generator were ported; its CSS targeted shadcn components, so the UI styles were **rewritten as CSS variables** over this app's own classes. The three original themes (Default, Classic, Light) are kept as options.
- **Two independent choices** (the accent colour setting was removed later; the accent belongs to the colour theme) + wallpaper, per device (`DeviceSettings`: `theme`, `ui`, `glass`, `wallpaper`, `wallpaperDarkness`, `wallpaperCustom`; old saved settings load fine). Applied by `lib/appearance.ts` `applyAppearance(settings)` (before first paint from `main.tsx`, and on every `updateSettings`).
- **Colour themes** (`lib/theme.ts`, `THEME_DEFS`): the 3 own themes (`own: true`, colours stay in `index.css`, no inline vars, Classic keeps its density/uppercase headings) + 17 colour themes + 16 platform palettes (Adwaita, Breeze, Win 11/10/7/XP/98, macOS, Material). Written as shadcn-style HSL values and translated by `curatorVars()` to this app's tokens (`--bg --surface --raised --line --hover --fg --muted --accent --accent-fg --good --warn --bad --top`) set inline on `<html>`; switching back to an own theme removes them. `--hover` is a new token (button hover; equals `--line` in the own themes). The handoff's `light` was renamed **Daylight** (id `daylight`) and its `dark` **Slate** (id `dark`) so ids don't collide with this app's Light/Default. "System" = Default (dark) / Light by the OS preference. Unknown ids fall back to Default.
- **UI styles** (`lib/uiStyle.ts` + `src/ui-styles.css`): default, GTK 4, Breeze, Win 11, Win 10, Win 7 (Aero), Win XP (Luna), Win 98, macOS, Material 3, set as `<html data-ui>`. A style is a block of variables (`--btn-*`, `--in-*`, `--card-*`, `--win-*`/`--tb-*`/`--close-*` for dialogs, `--menu-*`, `--nav-*`, `--row-*`, `--rng-*`, `--dur`/`--ease`, `--radius`, `--font`) read by the generic rules in the **second `@layer components` block of `index.css`** (`.btn`, `.input`, `.card`, `.bt-window`, `.bt-menu`, `.bt-nav`, `.bt-row`, `.bt-range`, ...). The first block of `ui-styles.css` holds defaults that reproduce the original look, and `default` sets nothing else. Because variables inherit from the nearest `[data-ui]`, the Settings preview (`PreviewApp`) renders its own style inside a page set to another. **Gotcha:** Tailwind 3 `@layer` is not a native cascade layer, it only orders output (base, components, utilities). Utility classes on an element (e.g. `px-5`, `justify-between`, `p-1`, `hover:bg-raised`) therefore beat the variable-driven component rules; markup that a style must control carries only the hook class (`bt-titlebar`, `bt-close`, `bt-menu`, `bt-nav`...) and no competing utilities. Extra selectors in `ui-styles.css` exist only where a look needs a ::selection, font size or bevel that variables can't express.
- Settings > Appearance (`components/AppearanceCard.tsx`): hover/focus previews an option in a framed preview, click applies; "Use matching colours" pairs a UI style with its platform palette. Wallpaper (`lib/wallpaper.ts`): generated SVG motif per theme or the user's picture (resized to 1920 px JPEG, kept in `localStorage` key `curator.wallpaperImage`, device-local), darkness slider; panels turn translucent when on.
- Verified in Chromium: every UI style on Tracks + a dialog, many themes, phone width (no horizontal scroll), wallpaper with and without a picture, accent contrast, old settings, reload persistence. Tests: `test/appearance.test.ts` (token completeness for all themes, ids, matching pairs, accent contrast).

## Sync design
Every row is a `SyncRecord {table,id,updatedAt,deviceId,deleted,data}`. Server assigns a monotonically increasing `seq`; clients pull `since=<cursor>`, push local changes. Conflicts: highest `updatedAt` wins, tie → higher `deviceId`. Deletes are tombstones. `votes`, `playbackLogs`, `timeline` are append-only (never conflict). Files are immutable, addressed by sha256; clients fetch missing hashes on demand or via "keep on this device".
Entities store **file hashes** (`image`, `cover`, `file`), never server paths. Elo/rating are never stored.
